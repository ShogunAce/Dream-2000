Dream 2000: app map

A snapshot of the code at commit b7f9392. It can drift as the code changes.

What it is

A browser app for counting outreach. You load a spreadsheet of companies and messages, copy a message, send it elsewhere, then log the answer. Each No earns XP toward 2,000 no's and each Yes earns a trophy. Everything is saved in your browser (localStorage); there is no server.

  • Landing page (src/pages/Landing.tsx): a first-person intro with a live counter.
  • Dashboard (src/pages/Dashboard.tsx): the cockpit with missions, waiting, results and campaign tabs.
  • Brain (src/lib/): spreadsheet parsing, the saved state, XP and rewards.

One action, end to end: load a sheet, open a card, copy the message

Reference route (3 stops)

1. The file comes in: src/components/dashboard/UploadPanel.tsx

Search for onFile. It hands the file to readMissionFile and, if that worked, calls loadMissions.

2. Rows become missions: src/lib/csv.ts

Search for parseMissionRows (column names to fields) and pickMessage (finds the real message even if a Yes/No column has a similar name). Tests for both live in src/lib/csv.test.ts.

3. The card shows it: src/components/dashboard/MissionPopup.tsx

Search for mission.message. The textarea displays it and the copy function writes it to the clipboard.

A practice to reuse: test with real-shaped data early

The plan assumed the message lived in a column called MESSAGE DRAFTED, and the sample file we made up matched that, so every test passed. The real spreadsheet used that name for a Yes/No flag and put the text in a column called Message, so the first real upload showed "Yes" on the card.

The fix was pickMessage in src/lib/csv.ts, with tests in src/lib/csv.test.ts built from the failing shape. On another project: put one real, messy example of your input in the first slice, and write the test from it before trusting the invented sample.

Run it again
